Rasterization—the technique powering standard rendering pipelines in modern game engines—is built on triangles: vertices are projected onto a 2D camera viewport, and pixels inside each triangle are interpolated and shaded.

**Ray Marching with Signed Distance Functions (SDFs)** takes the exact opposite philosophy:
There are no triangles. There are no vertex buffers. There is no geometry.

The entire 3D world is represented as a mathematical field:

```text
f(p) : R³ -> R
```

For any point p = (x, y, z) in space, f(p) returns the signed Euclidean distance to the nearest surface:
- f(p) &gt; 0: Point is in empty space outside geometry.
- f(p) = 0: Point sits exactly on the surface.
- f(p) &lt; 0: Point is inside solid geometry.

In my **Mini Ray Marcher** project, I engineered a real-time GPU ray marcher in GLSL and modern OpenGL. Here is the mathematics of sphere tracing, Constructive Solid Geometry, and procedural lighting.

## The Sphere Tracing Algorithm

Unlike ray tracing (which calculates analytical geometric intersections with polygons), ray marching steps a ray forward incrementally.

The genius of using an SDF is **Sphere Tracing** (introduced by John Hart):
Because f(p) tells us the *minimum distance to any obstacle*, we know that a sphere of radius R = f(p) centered at the ray position is **guaranteed to be empty**. We can safely jump forward by distance R in a single step without missing any surface!

```glsl
float rayMarch(vec3 ro, vec3 rd) {
    float t = 0.0; // Total distance traveled along ray
    
    for (int i = 0; i < 128; ++i) {
        vec3 p = ro + t * rd;
        float d = sceneSDF(p);
        
        // Hit surface condition
        if (d < 0.001) {
            return t;
        }
        
        // Ray escaped into infinity
        if (t > 100.0) {
            break;
        }
        
        t += d; // Safe forward jump
    }
    
    return -1.0; // Miss
}
```

Sphere tracing adapts automatically to the scene: in vast open spaces it takes huge forward strides; as it grazes intricate surfaces, steps become microscopic.

## Constructive Solid Geometry (CSG) and Smooth Minimum

Primitive SDF equations are remarkably elegant:

```glsl
// Sphere centered at origin with radius r
float sdSphere(vec3 p, float r) {
    return length(p) - r;
}

// Axis-aligned box with half-extents b
float sdBox(vec3 p, vec3 b) {
    vec3 q = abs(p) - b;
    return length(max(q, 0.0)) + min(max(q.x, max(q.y, q.z)), 0.0);
}
```

### Boolean Set Operators

Complex geometry is generated by composing primitives through CSG operations:

- **Union** (A ∪ B): `min(d1, d2)`
- **Intersection** (A ∩ B): `max(d1, d2)`
- **Subtraction** (A \ B): `max(d1, -d2)`

### Smooth Minimum (`smin`) for Organic Metaballs

Hard boolean unions create sharp, artificial intersections. To create organic, liquid-like melting between objects (metaballs), we use Inigo Quilez's **smooth polynomial minimum**:

```glsl
float smin(float a, float b, float k) {
    float h = clamp(0.5 + 0.5 * (b - a) / k, 0.0, 1.0);
    return mix(b, a, h) - k * h * (1.0 - h);
}
```

Where k controls the blending radius. When two geometric objects approach each other, their surfaces smoothly fuse together like drops of mercury.

## Estimating Normals via Tetrahedral Sampling

To compute lighting (diffuse and specular), we need the surface normal vector **n** at the hit point.

Because our geometry is defined purely by an equation, the surface normal is simply the **gradient of the scalar distance field**:

```text
n = normalize(∇f(p))
```

Rather than computing analytical derivatives for complex composite scenes, we approximate the gradient numerically.

The standard central difference method requires 6 scene evaluations. We can reduce this to **4 evaluations** using a symmetric tetrahedron:

```glsl
vec3 calcNormal(vec3 p) {
    const float h = 0.0005; // Step size
    const vec2 k = vec2(1.0, -1.0);
    
    return normalize(
        k.xyy * sceneSDF(p + k.xyy * h) +
        k.yyx * sceneSDF(p + k.yyx * h) +
        k.yxy * sceneSDF(p + k.yxy * h) +
        k.xxx * sceneSDF(p + k.xxx * h)
    );
}
```

## Ray-Marched Soft Penumbra Shadows

Hard shadows test binary visibility between the surface and the light source.

In ray marching, we get **soft penumbra shadows almost for free**. As we march a shadow ray toward the light source, we track how close the ray passes to any occluder:

```glsl
float calcSoftShadow(vec3 ro, vec3 rd, float mint, float maxt, float k) {
    float res = 1.0;
    float t = mint;
    
    for (int i = 0; i < 48 && t < maxt; ++i) {
        float h = sceneSDF(ro + t * rd);
        
        // Ray struck an obstacle
        if (h < 0.001) {
            return 0.0;
        }
        
        // Penumbra calculation: ratio of distance-to-surface over distance-along-ray
        res = min(res, k * h / t);
        t += clamp(h, 0.02, 0.20);
    }
    
    return clamp(res, 0.0, 1.0);
}
```

The parameter k controls shadow softness. If a shadow ray grazes an obstacle (h is small) far along its path (t is large), the penumbra factor smoothly darkens the fragment.

## Multi-Tap Ambient Occlusion

Ambient Occlusion (AO) approximates how much diffuse ambient light is blocked by nearby geometry (e.g. in crevices and corners).

With SDFs, AO can be calculated by sampling points along the surface normal **n** at increasing distances:

```glsl
float calcAO(vec3 p, vec3 n) {
    float occ = 0.0;
    float sca = 1.0;
    
    for (int i = 0; i < 5; ++i) {
        float h = 0.01 + 0.12 * float(i) / 4.0;
        float d = sceneSDF(p + h * n);
        occ += (h - d) * sca;
        sca *= 0.95;
    }
    
    return clamp(1.0 - 1.5 * occ, 0.0, 1.0);
}
```

If the surface is flat, d ≈ h, and occlusion remains zero. If the surface sits inside a concave corner, d &lt; h, and the crevice darkens naturally.

## Summary

| Technique | Polygon Rasterization | Ray Marching SDF |
| :--- | :--- | :--- |
| **Geometry Storage** | Megabytes of vertex arrays | **Zero bytes** (pure equations) |
| **CSG Operations** | Slow, complex boolean mesh slicing | **Trivial** (`min`, `max`, `smin`) |
| **Soft Shadows** | Complex shadow map PCF filters | **Integrated penumbra march** |
| **Ambient Occlusion** | Screen-space SSAO depth approximations | **Exact 3D geometric sampling** |
| **Surface Smoothness** | Limited by triangle polygon density | **Mathematically infinite resolution** |

Ray marching shifts the rendering burden entirely from memory bandwidth and geometry throughput onto pure arithmetic computation—making it the ideal playground for procedural shader engineering.
